# react-native-hinges 0.1.0-alpha.2

First functional alpha for native hinge posture and angles.

```sh
npm install react-native-hinges@0.1.0-alpha.2
```

Version `0.1.0-alpha.1` was not published to npm. This candidate fixes the local tarball path
in the publishing workflow; its native library code is unchanged.

## API

- `useHinges()` returns a read-only array of native posture and angle snapshots.
  Angles are radians; unavailable readings remain `null`.
- `createHingeObserver(rootTag)` supplies `get()` and `subscribe()` outside React.
  Observations belong to an existing React root; no provider or view ref is required.
- Optional `react-native-hinges/reanimated` exports `useAnimatedHinges()` for
  native updates to a Reanimated shared value on the UI runtime.
- iOS uses UIKit `UIHingeInteraction`. Android combines WindowManager posture
  with an unambiguously associated hinge-angle sensor. Posture is not inferred
  from angle thresholds, and array positions are not stable hinge identities.

## Requirements and migration

React Native's New Architecture is required. The tested example uses
`0.88.0-rc.1`; broader compatibility is not established. iOS observation requires
both the iOS 27.1 SDK and runtime, plus a host app using the UIScene lifecycle.
Older SDKs compile out observation even on newer devices. Android requires
API 24+, with API 30+ and an available sensor for angles.

The animated entry point additionally requires Reanimated `^4.7.0` and Worklets
`^0.13.0`; the example tests `4.7.0` and `0.13.0`. Its native event adapter depends
on current React Native/Reanimated internals, so dependency upgrades need validation.

The older `0.1.0-alpha.0` only reserved the package name. Install alpha.2, install
iOS pods, and rebuild the native app. Configure the optional peers for animated
consumers. Reserved-region geometry remains a separate package.

### Readiness-gated animated content

On the tested RN `0.88.0-rc.1` Android stack, conditionally mounting Reanimated
`4.7.0` content when `useReservedRegionsReady()` becomes true can throw
`__requestMapperRunFinalizer` is undefined: Worklets `0.13.0` can run synchronous
UI work ahead of queued mapper initialization. The combined hinges example uses
an [example-only Worklets FIFO patch](https://github.com/appandflow/react-native-hinges/blob/main/patches/react-native-worklets%400.13.0.patch).
Installing either library does not patch a consuming app's Worklets dependency.
Keeping the animated subtree mounted avoided this failure in the tested case;
apps that gate its mount need to apply the patch, rebuild the native app, and
validate it themselves.

## Verification and limits

- [Android 16/API 36 emulator checks](https://github.com/appandflow/react-native-hinges/blob/v0.1.0-alpha.2/docs/verification/root-observer-2026-09-20.md)
  covered fixed-angle startup, matching hook/observer/animated readings,
  navigation cleanup, and continued UI-runtime updates during a one-second JS
  stall. Input used native emulator sensor events and an AOSP fold override,
  not the app's simulated preview.
- [iOS 27.1 Duo simulator checks](https://github.com/appandflow/react-native-hinges/blob/v0.1.0-alpha.2/docs/verification/root-observer-ios-2026-09-20.md)
  delivered static closed/zero-angle readings to all three consumer types on
  startup and remount. Changing native iOS angles remain unverified.
- Both compiled entry points bundled from the packed tarball using Metro 0.87.1
  for Android. The core bundle passed with Reanimated/Worklets resolution denied;
  the animated subpath passed with its peers. The preceding native candidate's
  [CI](https://github.com/appandflow/react-native-hinges/actions/runs/35552275695)
  passed package checks and both native builds. Runtime reports describe their
  tested development builds, not a post-install test of the npm artifact.

There is no first-frame, sampling-frequency, frame-rate, or smoothing guarantee.
An uncached first render can return `[]`. The native cache clears after the last
subscriber; an externally retained animated shared value keeps its last snapshot.
Physical hardware, multiple live roots/windows, multiple-hinge hardware, and
Android release/R8 behavior remain unverified. Ambiguous sensor associations
return `null` angles.

The release-tag example includes the updated Field Notes artwork, readiness and
native-angle readouts, a measured-division marker, Sensor Lab, and the example-only
Worklets FIFO patch. It pins reserved-regions to GitHub commit `0c5a9ec`; switching
the example to the npm release is a separate post-publication update. Docusaurus
source is included in the repository; the sites remain local builds, with no
verified hosted deployment.
